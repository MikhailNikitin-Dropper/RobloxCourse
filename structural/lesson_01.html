Рабочее окружение студии (20 мин)

Интерфейс Roblox Studio (3.5 мин)

  • Mezzanine — плейтест и вкладки Home, Model, Script
  • Toolbar — панель инструментов активной вкладки
  • 3D viewport — интерактивное окно, где моделируем игровую сцену
  • Explorer — дерево всех объектов игры
  • Properties — настройки выбранного объекта

[изображение: Скриншот Studio с подписанными зонами: mezzanine, toolbar, viewport, Explorer, Properties]

Заметка ведущего: Показать в Studio: File → New → Baseplate, затем провести курсором по зонам в порядке слайда — вкладки, панель инструментов, окно сцены, Explorer, Properties. Показать: выделить Baseplate в Explorer — в Properties его свойства; выделить SpawnLocation — свойства сменились. Сказать: названия зон английские, как в самом Studio; перевод в скобках нужен, чтобы понять смысл. Если у ученика нет Explorer или Properties: вкладка View, кнопки Explorer и Properties.

Учимся летать камерой (2.5 мин)

  • W / A / S / D — двигать камеру вперёд/влево/назад/вправо
  • Q / E — вниз и вверх
  • F — сфокусироваться на выбранной детали
  • Зажать правую кнопку мыши — осмотреться вокруг
  • Колесо мыши — приблизить и отдалить (зум)
Заметка ведущего: Показать в Studio: курсор над окном сцены, W/A/S/D — полёт, E — вверх, Q — вниз, зажатая правая кнопка мыши — осмотреться. Показать: выделить SpawnLocation в Explorer, курсор над сценой, F — камера прилетает к детали. Сделать: минута свободного полёта у каждого. Если камера не двигается: курсор стоит над Explorer или Properties, а не над окном сцены.

Part: Move, Scale, Rotate (3.5 мин)

  • Part (деталь) — базовая форма: block (куб), sphere (шар), cylinder (цилиндр), wedge (клин)
  • Move (переместить) — стрелки по осям X/Y/Z
  • Scale (масштабировать) — изменение размера
  • Rotate (повернуть) — поворот детали

[изображение: Три кадра Roblox Studio подряд: одна и та же деталь с включённым инструментом Move (стрелки по осям), Scale (шарики на гранях) и Rotate (кольца поворота)]

Заметка ведущего: Показать в Studio: вкладка Home → Part — в сцене появился блок. Показать: по очереди Move, Scale, Rotate на той же вкладке — стрелки, шарики и кольца; потянуть за каждый маркер. Показать: стрелка под кнопкой Part — список форм: Block, Sphere, Cylinder, Wedge, Corner Wedge. Сказать: Move двигает, Scale меняет размер, Rotate поворачивает — это ответ на первый вопрос проверки.

Blockout: заготовка мира (3 мин)

  • Blockout (блокаут) — заготовка уровня из простых серых форм
  • Маршрут и масштаб — проверяем до декора
  • Серые формы легко переставлять, а декор переделывать долго
  • Локация — станет игрой уже на уроке 4
Заметка ведущего: Сказать: так начинают уровни в игровых студиях — серые формы, проверка маршрута, потом декор. Показать в Studio: из 4–5 деталей собрать комнату с проходом и пролететь через проход камерой. Сказать: эта заготовка станет игрой на уроке 4, а квест-лобби — на уроке 8; не удаляем. Сказать: level-дизайнеры в студиях не начинают с красоты; блокаут ещё называют grey-boxing (серобокс).

Group в Model и Anchored (3 мин)

  • Group (сгруппировать) — объединить детали в один Model: он двигается и копируется целиком
  • Понятные имена: StartRoom, Corridor вместо Part, Part1
  • Anchored (закреплено) = true — деталь не падает под действием физики при запуске
Заметка ведущего: Показать в Studio: выделить несколько деталей в Explorer с зажатым Ctrl → правый клик → Group — появилась Model. Показать: правый клик по Model → Rename, имя StartRoom. Показать: выделить деталь → в Properties галочка Anchored. Сказать: закрепляем почти все детали сцены — что будет без этого, покажем на слайде ошибок.

Проект живёт в облаке (1.5 мин)

  • Сохранение в облако: File → Save to Roblox отправляет твой мир на сервера Roblox
  • Конец каждого занятия — тот же File → Save to Roblox, одно действие
  • Studio сама ничего не хранит: без сохранения на следующем уроке придётся начинать с пустого места
Заметка ведущего: Показать в Studio: File → Save to Roblox — окно сохранения, название, кнопка Save. Сказать: File → Save to Roblox хранит проект в облаке; без сохранения на следующем уроке проекта не будет. Сказать: дальше то же действие обновляет проект — его делаем в конце каждого занятия. Если ученик работает на своём компьютере: можно добавить File → Save to File, но сохранение в облако обязательно.

Частые ошибки при блокауте (3 мин)

  • Anchored не включён — при запуске деталь падает, а собранная модель разваливается на части
  • Не проверять маршрут игрока по сцене — декор придётся переделывать
  • Давать деталям стандартные имена Part1, Part2 — нужный объект потом сложно найти в Explorer
  • Забыли сохранить проект в конце работы — он не появится в облаке

[изображение: Два кадра одной сцены рядом: слева собранная модель из деталей стоит на месте, справа та же модель без Anchored после запуска — детали упали и разъехались]

Заметка ведущего: Сказать: выключенный Anchored — самая частая ошибка на первом уроке. Показать в Studio: вставить Part, снять галочку Anchored, поднять деталь Move над полом → Test — деталь падает. Показать: то же с группой из нескольких деталей — модель разваливается. Сказать: Test открывает две вкладки, Client и Server; играем на Client, Stop закрывает обе. Показать: деталь Part1 в Explorer переименовать в StartWall — теперь её легко найти.

Проверяем теорию (4 мин)

Вопросы по теории (4 мин)

Чем Move (переместить) отличается от Scale (масштабировать)?

  1. Move меняет размер детали, а Scale её двигает
  2. Move двигает деталь, а Scale меняет её размер ✓
  3. Это одно и то же, просто разные кнопки

Зачем строить блокаут, если можно сразу украсить локацию?

  1. Чтобы локация с самого начала выглядела красиво
  2. Потому что в Studio нельзя сразу менять цвета
  3. Чтобы проверить маршрут и масштаб комнат до декора ✓

Что произойдёт с деталью при запуске, если не включить Anchored?

  1. Деталь упадёт, а собранная модель развалится на части ✓
  2. Ничего не изменится — Anchored влияет только на цвет
  3. Деталь станет невидимой сразу после запуска игры
Заметка ведущего: Ответы: Move двигает деталь, Scale меняет размер; блокаут — чтобы проверить маршрут и масштаб до декора; без Anchored деталь упадёт, а модель развалится на части. Если на третий вопрос не отвечают: повторить Test с незакреплённой деталью со слайда ошибок.

Строим свой первый блокаут (20 мин)

Задача практики (2 мин)

  • Квест-лобби — заготовка уровня
  • Комнаты — 2–3 условные комнаты
  • Проходы — соединяют комнаты между собой
  • Основа проекта — пригодится уже на следующем уроке
Заметка ведущего: Показать в Studio: готовую заготовку из 2–3 комнат с проходами — ученики видят, что получится. Сказать: только серые детали; цвет и материалы — на следующих уроках. Сказать: на уроке 4 эта заготовка станет игрой, а к уроку 8 вырастет в квест-лобби — строим на будущее.

Шаг 1: пол и стены (7 мин)

  1. Полетать камерой по сцене
  2. Вставить Part и с помощью Scale растянуть его до размеров пола
  3. Скопировать Part и поставить 3–4 стены
Заметка ведущего: Проверить у каждого: пол — плоская Part, растянутая Scale; 3–4 стены стоят на полу, а не висят в воздухе. Показать при затруднении: Ctrl+D копирует деталь, копию сразу сдвигаем Move. Если ученик красит детали: вернуть к серым формам, цвет — на следующих уроках. Напомнить: полёт — W/A/S/D + зажатая правая кнопка мыши, F — фокус на детали; стены — копии Part, их двигают Move и растягивают Scale по периметру пола.

Шаг 2: проход и комната (5 мин)

  1. Оставить проход в одной стене
  2. Пристроить коридор
  3. Достроить финальную комнату и пролететь маршрут
Заметка ведущего: Проверить у каждого: камерой можно пролететь из стартовой комнаты через коридор в финальную, проход не закрыт стеной. Сказать: проход делаем не уже 4 студов — уже на уроке 4 по нему пойдёт персонаж, а не камера.

Шаг 3: группы и закрепление (3 мин)

  1. Сгруппировать детали зоны в Model
  2. Назвать модели: StartRoom, Corridor, FinalRoom
  3. Включить Anchored у всех Part
Заметка ведущего: Показать в Studio: выделить детали комнаты в Explorer с зажатым Shift → правый клик → Group → правый клик → Rename. Проверить у каждого: Test — ничего не падает; упавшую деталь найти в Explorer и включить Anchored. Сказать: группа — кнопка Group; без Anchored блокаут развалится при запуске.

Шаг 4: сохранение (3 мин)

  1. File → Save to Roblox…
  2. Придумать название, нажать Save
  3. Убедиться, что проект появился в списке своих игр
Заметка ведущего: Показать в Studio: File → Save to Roblox → название → Save. Проверить у каждого: на сайте Roblox в разделе Creations появилась карточка проекта с этим названием. Сказать: повторное сохранение — тот же File → Save to Roblox.

Обсуждаем практику (4 мин)

Вопросы по практике (4 мин)

Зачем называть модели StartRoom, Corridor и FinalRoom?

  1. Чтобы детали сами закрепились после запуска игры
  2. Чтобы Studio сама сохранила проект в облако
  3. Чтобы быстро найти нужную зону в Explorer ✓

Как проверить, что все детали блокаута закреплены?

  1. Нажать Test — ничего не должно упасть ✓
  2. Посмотреть на цвет деталей в сцене
  3. Заново переименовать каждую деталь в Explorer

Как убедиться, что проект сохранился в облаке?

  1. Нажать Test и дождаться запуска игры
  2. Найти проект в списке своих игр ✓
  3. Проверить, что Studio не показал ошибок
Заметка ведущего: Ответы: имена — чтобы найти зону в Explorer; закрепление проверяем Test — ничего не падает; сохранение — проект есть в списке своих игр. Проверить у каждого: 2–3 связанные комнаты и проект, сохранённый в облаке. Если при Test деталь падает: вместе найти её в Explorer и включить Anchored.
